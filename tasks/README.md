# 작업 보드 — 프론트엔드 (`fe-*` 티켓)

백엔드 티켓은 백엔드 리포 `tasks/`에 있다. **번호는 두 리포가 공유**한다.

> **이 보드는 "무엇을 어떻게"만 말한다.** 날짜별 전체 순서 · 저녁 체크포인트 ·
> 일정이 밀릴 때 버리는 순서는 백엔드 리포
> [`docs/참고/전체로드맵.md`](../../UDT-Used_Device_Trade-backend/docs/참고/전체로드맵.md)에 있다.
> **아침에 로드맵에서 오늘 칸을 열고, 거기 적힌 티켓을 여기서 찾는다.**
> **내 티켓을 어떤 순서로, 어떻게 하는지는 [`../onboarding/역할별/`](../onboarding/역할별/) 의
> 내 코드 파일 5번 절**에 단계별로 적혀 있다 — 이 보드보다 그쪽이 자세하다.

## 의존 순서

```
T-011 (환경·공용)
  ├── T-012 (인증 화면) ──▶ 이후 모든 보호 화면의 전제
  ├── T-013 (목록) ── T-014 (상세) ── T-015 (등록)
  ├── T-016 (마이페이지) ── T-017 (거래 상세)
  └── T-020 (반응형) ← 화면이 다 생긴 뒤
```

## 공통 규칙 (모든 티켓에 적용)

- 서버 통신은 `src/api/` 에서만 — 컴포넌트에서 `axios`·`fetch` 직접 호출 금지
- 화면마다 **네 상태**(로딩·정상·빈 결과·에러)를 전부 만든다
- 검색어·필터·페이지는 **URL 쿼리**. Zustand는 `authStore`·`wishStore` 둘뿐
- 색·간격은 `styles/tokens.css` 의 `var(--...)` 만
- props를 받는 컴포넌트마다 `propTypes` (props 없는 페이지 컴포넌트는 제외)
- **`pages/<내화면>/` 밖은 FE-A 소유다.** 공용 파일이 필요하면 FE-A에게 요청한다

**`pages/ProductListPage/` 가 기준 구현이다.** 네 상태·검색·페이징이 다 들어 있으니
새 화면은 그 구조를 따른다.
