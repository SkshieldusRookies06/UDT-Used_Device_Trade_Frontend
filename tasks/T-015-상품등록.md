# T-015 — 상품 등록 · 이미지 미리보기

**담당:** FE-B · **브랜치:** `fe-product-new` · **예상:** D5~D6 · **선행:** T-012 · T-014

## [배경]

계약 (`SPEC.md` §4.4):

```
POST /api/products   multipart/form-data
  파트: product (JSON Blob) + images (0~5개)
  제약: jpg/png/webp · 각 5MB · 최대 5장
  성공 201 · status 는 항상 INSPECTING
  에러: 400 VALIDATION_ERROR(+fields[]) · FILE_TYPE_NOT_ALLOWED · FILE_TOO_LARGE
```

`api/products.js`의 `createProduct(product, images)` 가 이미 multipart 조립을 한다.

**검증의 정본은 백엔드 400이다.** 프론트 검증은 왕복을 줄이는 장치일 뿐이고,
문구는 서버가 주는 것을 쓴다.

## [목표]

사진을 붙여 상품을 등록하고, 검수 대기 안내를 본다.

## [수용 기준]

- [ ] 카테고리 select — `GET /api/categories` 로 채운다
- [ ] 이미지 선택 시 **미리보기** (`URL.createObjectURL`) · 개별 삭제 가능
- [ ] **`URL.revokeObjectURL`로 정리**한다 (언마운트·삭제 시 — 메모리 누수 방지)
- [ ] 6장 선택 시 프론트에서 먼저 안내 (그래도 서버 검증이 정본)
- [ ] 제출 중 버튼 비활성
- [ ] 검증 오류 → **`fields[]`를 각 입력 아래에** 표시
- [ ] 성공 → **"관리자 검수 후 판매중으로 전환됩니다"** 안내 후 `/mypage` 이동
- [ ] `npm run build` 에러 0

> **안내 문구를 빠뜨리지 않는다.** 없으면 등록한 상품이 목록에 안 보이는 것을
> 고장으로 오해한다 — 시연에서 가장 자주 나오는 질문이다.

## [제약]

- 수정 허용: `pages/ProductNewPage/` · `api/products.js`(FE-B 소유)
- **`createProduct` 시그니처를 바꾸려면 T-013·T-014를 같이 고친다** — 세 화면이 같은 파일을 쓴다
- 파일을 base64로 바꾸지 않는다 — multipart 그대로 보낸다
- 등록 후 목록을 강제로 새로고침하지 않는다 (어차피 검수 전이라 안 보인다)

## [확인 명령]

```bash
npm run build
```
