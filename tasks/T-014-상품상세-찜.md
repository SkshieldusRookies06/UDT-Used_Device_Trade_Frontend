# T-014 — 상품 상세 · 찜 · 구매

**담당:** FE-B · **브랜치:** `fe-product-detail` · **예상:** D2~D3 · **선행:** T-012 · T-013

## [배경]

계약 (`SPEC.md` §4.3 · §4.5 · §4.9):

```
GET    /api/products/{id}               data 는 객체 · images[] (0장이면 []) · wished(bool)
POST   /api/products/{id}/wishes   201  {productId, wished:true,  wishCount}
DELETE /api/products/{id}/wishes   200  {productId, wished:false, wishCount}
POST   /api/products/{id}/purchase 201  거래 객체 → /transactions/{id} 로 이동

에러: 409 PRODUCT_NOT_ON_SALE · 400 SELF_PURCHASE_NOT_ALLOWED
      400 INSUFFICIENT_BALANCE · 409 WISH_ALREADY_EXISTS · 404 PRODUCT_NOT_FOUND
```

`wishStore`는 **목록·상세·마이페이지 3화면이 공유**한다. 상세에서 찜하면 목록으로
돌아갔을 때도 반영되어야 한다.

## [목표]

상세를 보고 찜·구매할 수 있다. 구매 실패 사유가 화면에 정확히 뜬다.

## [수용 기준]

- [ ] 사진 갤러리 — `images[]` 가 **0장이어도 깨지지 않는다** (`[]` 처리)
- [ ] 찜 토글 → 버튼 상태·`wishCount` 즉시 반영 · **`wishStore` 갱신**
- [ ] 목록으로 돌아가면 찜 상태가 유지된다
- [ ] 비로그인 찜/구매 시도 → `/login` 이동
- [ ] 구매 성공 → `/transactions/{id}` 이동
- [ ] **구매 실패 3종이 각각 다른 문구로 뜬다** (서버 `message` 그대로)
      - 잔액 부족 → "잔액이 부족합니다"
      - 본인 상품 → "본인이 등록한 상품은 구매할 수 없습니다"
      - 이미 거래중 → "판매 중인 상품이 아닙니다"
- [ ] 없는 상품 id → 404 안내 + 목록 링크 (흰 화면 아님)
- [ ] 화면 상태 4종 구현
- [ ] `npm run build` 에러 0

## [제약]

- 수정 허용: `pages/ProductDetailPage/` 만
- **`store/wishStore.js` 수정이 필요하면 FE-A에게 요청한다**
- 구매 버튼은 요청 중 비활성 — 중복 구매 요청이 나가면 안 된다
- 에러 문구를 프론트에서 새로 만들지 않는다
