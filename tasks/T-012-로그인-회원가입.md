# T-012 — 로그인 · 회원가입 화면

**담당:** FE-A · **브랜치:** `fe-auth` · **예상:** D2~D3 · **선행:** T-011

## [배경]

계약 (`SPEC.md` §4.1 · §3.4):

```
POST /api/auth/signup  201  data = {id, email, nickname}   · 409 EMAIL_ALREADY_EXISTS
POST /api/auth/login   200  data = {accessToken, user:{id, nickname, role, balanceKrw}}
                            · 401 INVALID_CREDENTIALS
GET  /api/me           200  data = {id, email, nickname, role, balanceKrw}
```

**토큰 만료 시 동작** — 인터셉터가 `authStore`를 비우고 `/login`으로 이동한다.
**안내 문구("다시 로그인해 주세요")는 아직 없다** — SPEC §3.4가 요구하므로 **이 티켓에서 `LoginPage`가**
`?reason=expired` 같은 신호를 읽어 띄운다. 인터셉터 자체는 건드리지 않는다.
`/api/auth/**` 응답은 이 처리에서 **제외**한다(로그인 실패도 401이라 무한 리다이렉트가 된다).
`src/api/client.js`에 이미 구현돼 있으니 **동작을 확인만** 한다.

보호 라우트: `/products/new` · `/mypage` · `/transactions/:id` — `RequireAuth`가 감싼다.
로그인 후에는 **원래 가려던 화면으로 돌아간다**(`location.state.from`).

## [목표]

로그인하면 헤더가 바뀌고 보호 화면에 들어갈 수 있다.

## [수용 기준]

- [ ] `pages/LoginPage/` · `pages/SignupPage/` 구현
- [ ] 로그인 성공 → `authStore.setAuth(token, user)` → **헤더에 닉네임·잔액·로그아웃**이 뜬다
- [ ] 로그인 실패 → "이메일 또는 비밀번호가 올바르지 않습니다" (**서버 `message` 그대로**)
- [ ] 회원가입 중복 이메일 → "이미 가입된 이메일입니다"
- [ ] 제출 중 버튼 비활성 (중복 제출 방지)
- [ ] **새로고침해도 로그인이 유지된다** (`authStore` persist)
- [ ] 비로그인으로 `/mypage` 진입 → `/login` 이동 → 로그인 후 **`/mypage`로 복귀**
- [ ] 로그아웃 → 헤더가 "로그인 / 회원가입"으로 돌아간다
- [ ] `npm run build` 에러 0

## [제약]

- 수정 허용: `pages/LoginPage/` · `pages/SignupPage/` · `components/Layout.jsx`(헤더)
- **`api/client.js`의 인터셉터를 바꾸지 않는다** — 동작 확인만. 문제가 있으면 보고
- 에러 문구를 프론트에서 새로 쓰지 않는다 — 서버 `message`를 그대로 쓴다
  (두 벌이 되면 화면과 서버가 다른 말을 한다)
- 비밀번호를 콘솔에 찍지 않는다

## [확인 명령]

npm run build

## 백엔드 대기 없이 하는 법

목 서버가 `POST /api/auth/login`을 이미 구현하고 있다(`buyer1@udt.test` / `Test1234!`).
백엔드 T-005가 끝나면 목을 끄기만 하면 된다.
