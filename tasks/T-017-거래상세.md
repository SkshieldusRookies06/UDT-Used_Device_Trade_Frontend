# T-017 — 거래 상세 (상태별 액션 · 분쟁 신고)

**담당:** FE-C · **브랜치:** `fe-transaction` · **예상:** D3~D5 · **선행:** T-016
**이 화면이 서비스의 중심이다.**

## [배경]

계약 (`SPEC.md` §4.5~4.8):

```
GET   /api/transactions/{id}             당사자만 · 403 TRANSACTION_FORBIDDEN
PATCH /api/transactions/{id}/shipping    판매자만 · PAID 상태에서만
      body {courier, trackingNo}         trackingNo 숫자 8~20자리
PATCH /api/transactions/{id}/confirm     구매자만 · SHIPPING 상태에서만
POST  /api/transactions/{id}/disputes    구매자만 · multipart (dispute JSON + files 0~3)
                                         reason 10~500자
GET   /api/disputes/{id}/files/{fileId}  다운로드
```

**상태 × 역할에 따라 버튼이 달라진다** (`docs/04-화면설계서.md` SCR-005):

| 거래 상태 | 구매자에게 | 판매자에게 |
|---|---|---|
| 결제완료 | 분쟁 신고 | **배송 정보 입력** |
| 배송중 | **구매 확정** · 분쟁 신고 | (대기) |
| 구매확정 | 완료 표시 | 완료 표시 |
| 분쟁 | 접수 내역 · 증빙 목록 | 접수 내역 |
| 환불완료 | 환불 안내 | 환불 안내 |

## [목표]

거래 당사자가 자기 차례의 액션만 볼 수 있고, 분쟁을 증빙과 함께 신고할 수 있다.

## [수용 기준]

- [ ] **상태 × 역할 조합에 맞는 버튼만** 보인다 (위 표 그대로)
- [ ] 내가 구매자인지 판매자인지 **응답의 `buyerId`·`sellerId`와 `authStore.user.id`를 비교**해 판정한다
      (닉네임으로 판정하지 않는다 — 중복될 수 있다 · SPEC §4.5)
- [ ] 송장 입력 폼 — 택배사 + 송장번호 · 형식 오류 시 `fields[]` 표시
- [ ] 구매 확정 → **확인 대화상자** 후 실행 (되돌릴 수 없는 동작)
- [ ] 분쟁 신고 폼 — 사유(10~500자) + 파일 0~3개 · 미리보기
- [ ] 분쟁 접수 후 증빙 파일 목록이 보이고 **누르면 실제로 내려받아진다**
- [ ] 액션 실행 중 버튼 비활성 · 완료 후 화면 갱신
- [ ] 제3자 접근 → **403 안내**("해당 거래의 당사자가 아닙니다") · 흰 화면 아님
- [ ] 화면 상태 4종
- [ ] `npm run build` 에러 0

## [제약]

- 수정 허용: `pages/TransactionDetailPage/` · `api/transactions.js`(FE-C 소유)
- **상태 판정 로직을 화면에 흩지 않는다** — 한 함수에 모아 둔다
      (`canConfirm(txn, me)` · `canRegisterShipping(txn, me)` 식)
- 다운로드는 **`api/transactions.js`의 `downloadDisputeFile()`** 로 — `<a href>` 로는 안 된다.
  `/api/**`는 JWT 헤더 인증이라 브라우저 주소창 이동에는 토큰이 실리지 않는다(401). blob으로 받아 내려받는다
- 구매확정처럼 되돌릴 수 없는 동작은 **반드시 확인 단계**를 둔다

## [확인 명령]

```bash
npm run build
```
