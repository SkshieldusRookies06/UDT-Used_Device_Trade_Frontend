# 프론트 사람 게이트 — 하루 1회 · 담당 오너가 직접 클릭

> `check-api`는 "계약대로 읽을 수 있는가"까지만 답한다. **화면이 말이 되는가는 사람이 본다.**
> 아래 체크리스트 통과가 곧 수용 기준이다. "잘 보이면"은 수용 기준이 아니다.

## 기계 (먼저 · 실패하면 아래를 안 본다)

```
cd frontend && npm run build          → 에러 0
cd frontend && npm run preview        → D4·D8은 dev가 아니라 빌드물에서 본다
```

**콘솔 에러 0의 정의:** Uncaught 예외 · 실패한 요청(빨간 4xx/5xx·CORS) 0.
React 개발 경고(`unique "key" prop`)는 세지 않는다.

## 사람 — 5줄 (매일)

| # | 확인 | 트리거 (명령 수준으로) |
|---|---|---|
| 1 | **정상** — 목록에 상품 카드가 보이고 썸네일·가격·상태 배지가 뜬다 | `/`에 진입 |
| 2 | **빈 결과** — "조건에 맞는 상품이 없습니다"가 뜬다 (무한 스피너 아님) | 검색창에 `__none__` 입력 |
| 3 | **로딩** — 스피너가 뜨고 제출 버튼이 비활성된다 | DevTools Network → Throttling `Slow 3G` 후 새로고침 |
| 4 | **에러** — 에러 문구 + 재시도 버튼이 뜬다 (흰 화면 아님) | DevTools Network → `Offline` 체크 후 재시도 |
| 5 | **반응형** — 390px에서 목록이 1열, 가로 스크롤 0 | DevTools 기기 툴바 → 390 · 768 · 1280 |

## 관리자 (Thymeleaf · BE-C 담당 · D6부터)

| # | 확인 | 트리거 |
|---|---|---|
| 6 | `/admin/login` 로그인 후 검수 대기 목록이 보인다 | 시드 관리자 계정 |
| 7 | 반려 사유를 비우고 제출하면 **같은 폼에 에러 문구**가 뜬다 (PRG 검증 실패 경로) | 반려 버튼 · 사유 공란 |

## 시연 경로 (D8 · D10 리허설 · 시연 PC에서)

SPEC.md §1-2 완료 그림 ①~⑦을 끊김 없이 1회. **리허설은 2회 — 1회는 리허설이 아니라 첫 실행이다.**

---

**실서버로 전환한 뒤 2번(빈 결과) 트리거가 사라지면 그 줄은 조용히 체크만 된다.**
시드에 없는 검색어(`__none__`)를 계속 쓰는 이유가 이것이다 — SPEC §3.3의 계약 값이다.
