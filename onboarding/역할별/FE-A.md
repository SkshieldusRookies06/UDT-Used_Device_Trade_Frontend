## 1. 한 줄로

**내가 만든 바닥 위에서 FE-B·FE-C가 화면을 그린다.** 라우팅·axios 인스턴스·인터셉터·스토어·토큰·공용 컴포넌트가 내 것이다.
기능 화면은 2장(로그인·회원가입)뿐이지만, **공용 파일은 전부 내 소유**라서 두 사람이 나를 기다리는 일이 자주 생긴다 — 요청이 오면 빨리 쳐낸다.

### 내가 소유한다 (내가 결정한다)

### 절대 안 건드린다

- 남의 `pages/` 폴더 — `ProductListPage` · `ProductDetailPage` · `ProductNewPage`(FE-B) · `MyPage` · `TransactionDetailPage`(FE-C)
- `src/api/products.js`(FE-B) · `src/api/transactions.js`(FE-C)
- 백엔드 리포 전체 — **계약이 틀려 보여도 내가 고치지 않는다.** BE 짝에게 보고
- `seams/gate.mjs` — **게이트를 통과시키려고 게이트를 고치지 않는다**

### 공용 — 만지기 전에 채널에 한 줄 올린다

| 파일 | 규칙 |
|---|---|
| `package.json` · `package-lock.json` | 내 소유지만 **의존성 추가는 채널 선공지 후 커밋**. lock 충돌은 손으로 병합하지 않고 main의 `package.json`을 받아 재생성 |
| `styles/tokens.css` | 내 소유. 값이 바뀌면 화면 전부가 바뀌니 **바꿀 때 공지** |
| `*.module.css` (T-020 반응형) | **이 티켓만 남의 `pages/`를 만진다.** D7 하루에 끝내고 당일 머지 · 그날 FE-B·FE-C는 CSS를 안 건드린다 |

> 남의 파일이 틀려 보여도 고치지 않는다. **오너에게 보고**한다.
> 고치면 그 버그의 책임이 나에게 넘어온다.

## 3. 내 계약 상대

| 나 | 상대 | 무엇에 대해 |
|---|---|---|
| **FE-A** | **BE-B** | 로그인·회원가입 · **토큰 만료 시 화면이 어떻게 되는가** |

**합의는 `SPEC.md`에 커밋되기 전까지 무효다.**

> D1 회의에서 BE-B와 이것부터 정한다 — **토큰 만료 시간 · 재발급 여부 · 401을 받았을 때의 화면 동작**.
> 이게 안 정해지면 인터셉터를 쓸 수 없고, 그러면 FE-B·FE-C의 보호 화면도 전부 막힌다.

> 그리고 **FE-B·FE-C의 공용 파일 요청 창구가 나다.** 30분 안에 답하거나 "언제 보겠다"를 답한다.
>
> **요청이 밀리지 않게 두 가지를 정해 둔다:**
> - 요청은 채널에 **한 줄 양식**으로만 받는다 — `[공용요청] <파일> · <필요한 것 한 줄> · <내 티켓>`.
>   양식이 없으면 "양식으로 다시요". 말로 받은 요청은 잊힌다.
> - **매일 14:00 30분**을 공용 요청 처리 시간으로 고정한다. 그 시간엔 내 티켓을 안 잡는다.
>   급한 건 30분 규칙대로 즉시, 나머지는 14:00에 몰아서. FE-B·FE-C도 이 시간을 안다.

### T-011 — 기동 확인·공용 구조 점검 (D1 오전 · 두 사람이 나를 기다린다)

**1) 내 PC부터 띄운다**

```bash
npm ci
cp .env.example .env          # VITE_API_URL=http://localhost:8080
npm run dev                   # http://localhost:5173
```
> **주소창에 `127.0.0.1`을 쓰지 않는다.** `localhost`와 다른 origin이라 CORS가 막는다.

**2) 목 서버를 띄운다** (다른 터미널) — 백엔드를 기다리지 않는 장치다

```bash
npm run mock      # 백엔드 리포의 mock/server.mjs 를 실행한다
```
`확인:` `localhost:5173` 에 상품 목록이 실제로 뜬다.

**3) 게이트를 돌린다**

```bash
npm run gate      # 9/9 ok
```
백엔드 리포가 형제 폴더가 아니면 `BACKEND_REPO=<경로> npm run gate`.

**4) 공용 파일 6개를 읽는다 ← 이게 T-011의 진짜 내용이다**
FE-B·FE-C가 이 파일들 위에서 일한다. **내가 모르면 두 사람의 질문에 답할 수 없다.**

| 파일 | 읽으면서 확인할 것 |
|---|---|
| `src/api/client.js` | **인터셉터가 봉투를 벗긴다**(`res.data.data`) · 401이면 로그아웃 후 `/login` · 로그인 API는 예외 |
| `src/store/authStore.js` | 토큰을 어디에 두는가 · 새로고침 후 복원되는가 |
| `src/routes.js` | 경로 문자열은 **여기서만** 나온다 |
| `src/App.jsx` | `errorElement` · `path="*"` 가 걸려 있는가 |
| `src/styles/tokens.css` | 색·간격 변수 이름 |
| `src/components/` | 6종이 무엇을 받는지 (`propTypes`) |

**5) `pages/ProductListPage/` 를 읽는다 — 팀의 기준 구현이다**
네 상태·검색·페이징이 다 들어 있다. FE-B·FE-C가 이 구조를 따라간다.

**6) FE-B·FE-C를 붙인다**
각자 1~3번을 돌리게 하고 막히면 같이 본다.

`확인:` **프론트 3명 전원이 `npm run dev` + `npm run mock` 으로 화면을 봤다.**

### T-012 — 로그인·회원가입 화면 (D2~D3)

`pages/LoginPage/` · `pages/SignupPage/` 가 **골격만 있다.** 채운다.

**1) 먼저 BE-B와 토큰 동작을 확정한다** (D1 회의에서 이미 했어야 한다)
만료 시간 · 재발급 여부 · 401을 받은 화면의 동작. **`SPEC.md`에 적히기 전까지 무효다.**

**2) `LoginPage` 를 만든다**

```
1) 이메일·비밀번호 폼
2) submit → api/auth.js 의 login() → 토큰을 authStore 에 저장
3) 성공하면 원래 가려던 곳으로 (없으면 "/")
4) 실패하면 서버의 message 를 그대로 띄운다  ← 문구를 새로 쓰지 않는다
5) 요청 중에는 버튼 비활성
```
> 서버는 로그인 실패를 **401 `INVALID_CREDENTIALS` 하나**로만 낸다.
> "이메일이 없습니다"와 "비밀번호가 틀립니다"를 구분해 보여 주지 않는다 — 계정 열거를 막는 설계다.

**3) `SignupPage` 를 만든다**

```
1) 이메일·비밀번호·닉네임
2) 서버 검증 에러의 fields[] 를 해당 입력 밑에 붙인다  ← 이게 봉투에 fields 가 있는 이유다
3) 성공하면 로그인 화면으로
```

**4) `RequireAuth` 가 도는지 확인한다**
비로그인으로 `/mypage`에 가면 `/login`으로 튕기고, 로그인 후 `/mypage`로 돌아와야 한다.

**5) 401 동작을 직접 만들어 본다**
`authStore`의 토큰을 개발자도구에서 망가뜨리고 보호 화면을 새로고침한다.
`확인:` 인터셉터가 로그아웃시키고 `/login`으로 보낸다.

**6) 네 상태를 다 만든다** — 로딩 · 정상 · 빈 결과 · 에러. 인증 화면은 "빈 결과"가 없으니 셋.

`확인:` 목 서버로 로그인 → 토큰 저장 → 보호 화면 진입 → 토큰 망가뜨리면 튕김.

### T-020 — 반응형 3뷰포트 + 캡처 (D7 · ★ 제출 자료)

**이 티켓만 남의 `pages/`를 만진다.** 그래서 규칙이 하나 더 있다.

**1) 착수 전에 채널에 올린다**
"지금부터 CSS 만집니다. FE-B·FE-C는 오늘 `*.module.css`를 건드리지 마세요. JSX는 계속하셔도 됩니다."

**2) 브레이크포인트를 `tokens.css`에 상수로 넣는다**

```css
/* 390 모바일 · 768 태블릿 · 1280 데스크톱 */
```
> 화면마다 다른 숫자를 쓰면 D8에 어긋난 곳이 나온다. **세 개만 쓴다.**

**3) 화면을 하나씩 돈다** — 목록 → 상세 → 등록 → 마이페이지 → 거래 상세 → 로그인/회원가입

각 화면에서 **CSS로만** 고친다. **JSX 구조를 바꾸지 않는다** — 바꾸면 그건 남의 코드를 고치는 것이다.
구조를 바꿔야만 풀리는 게 있으면 **오너에게 요청**한다.

**4) 색·간격 리터럴을 새로 넣지 않는다**

```bash
grep -rnE "#[0-9a-fA-F]{3,6}" src --include='*.module.css'   # 무출력이 정상
```

**5) 캡처 3장을 찍는다** — 개발자도구에서 390 · 768 · 1280

```
docs/images/responsive-390.png
docs/images/responsive-768.png
docs/images/responsive-1280.png
```
> **같은 화면**을 세 폭으로 찍는다. 상품 목록이 가장 잘 보인다.

**6) 그날 안에 머지한다.** 하루를 넘기면 FE-B·FE-C가 이틀을 못 움직인다.

`확인:` `npm run build` 에러 0 · 위 grep 무출력 · 캡처 3장 · **당일 머지 완료**.

## 9. 내가 막힐 곳 (내 역할 고유)

| 증상 | 원인 | 볼 곳 |
|---|---|---|
| CORS 에러 | 주소창이 `127.0.0.1`이다 | **`localhost`로만 연다** — 다른 origin이다 |
| `npm run gate` 가 백엔드를 못 찾는다 | 형제 폴더가 아니다 | `BACKEND_REPO=<경로> npm run gate` |
| 응답에서 `data`를 두 번 벗긴다 | 인터셉터가 이미 벗겼다 | `api/client.js` — **봉투 해제는 한 곳에서만** |
| 토큰 만료 후에도 화면이 그대로 | 401 처리가 없다 | 인터셉터에서 401 → 로그아웃 → `/login`. **BE-B와 합의한 동작대로** |
| 로그인 API만 401을 다르게 처리해야 한다 | 로그인 실패는 만료가 아니다 | `url.startsWith("/api/auth/")` 로 분기 |
| 새로고침하면 로그아웃된다 | 토큰을 메모리에만 뒀다 | authStore 초기화 시 복원 |
| 실서버로 바꿨더니 첫 요청부터 401 | localStorage에 **목 서버가 준 가짜 토큰**이 남아 있다 (`authStore` persist) | 개발자도구 → Application → Local Storage 비우고 다시 로그인. D4 아침 프론트 전원에게 공지 |
| Zustand를 더 만들고 싶다 | 검색·필터·페이지는 **URL이 정본**이다 | 스토어는 `authStore`·`wishStore` **둘뿐** |
| FE-B·FE-C 요청이 계속 쌓인다 | 공용 파일이 전부 내 것이라 자연스러운 일 | D5~D6을 지원에 쓴다. 내 기능을 그때 잡지 않는다 |

말할 것 세 가지:
1. **컴포넌트 구조** — 공용 6종 + 화면별 폴더. 라우트 1개 = 폴더 1개 = 담당 1명
2. **상태 관리** — Zustand는 둘뿐. **검색·필터·페이지는 URL이 정본** (새로고침·뒤로가기·공유가 다 된다)
3. **반응형 3뷰포트** — 캡처 3장을 띄우고 말한다

> Q&A 방어 중 내 몫: **"결과가 없으면 화면이 어떻게 되나"**
> → "화면마다 **네 상태**를 다 만들었습니다 — 로딩·정상·**빈 결과**·에러. 빈 결과는 에러가 아닙니다."

## 11. 매일 하는 것 (전원 공통 · 합쳐서 10분)

**아침 3문장 (스탠드업 · 15분 캡)**

```
1) 어제 머지한 것 — 커밋 해시 + 게이트 green/red 로 말한다 ("70% 됐어요" 금지)
2) 오늘 여는 티켓 하나
3) 막힌 것 — 30분 넘게 막혔으면 여기서 반드시 말한다
```

**하루 끝 (5분)**

```
1) 위 7번 게이트 명령 1회 → green
2) git diff 를 내가 읽는다. 한 화면(약 100줄)을 넘으면 머지하지 않고 티켓을 쪼갠다
3) 커밋·push는 내가 한다 → 오너에게 머지 요청
4) worklog/<내이름>/D##.md 에 3줄
   1) 머지: T-0XX · a1b2c3d · 게이트 OK
   2) 열었음: T-0XX
   3) 막힘: (있으면 한 줄 · 없으면 "없음")
```

**30분 규칙** — 30분 막히면 채널에 올린다. 질문은 팀 일정을 구하는 행위다.
답하는 쪽은 30분 안에 답하거나 "언제 보겠다"를 답한다.

## 12. 내가 지키는 네 줄

```
1. SPEC.md에 답이 없으면 추측하지 않는다 — 멈추고 오너에게 묻는다
2. "됐습니다"는 증거가 아니다 — 게이트 출력이 증거다
3. 위 2번 밖의 파일은 틀려 보여도 고치지 않는다 — 오너에게 보고
4. 계약에 대한 구두 합의는 SPEC.md에 커밋되기 전까지 무효
```

에이전트에 맡길 때는 **지시서(`tasks/T-###.md`) + SPEC 해당 절 + (수정이면) diff** 셋만 넣는다.
리포를 통째로 넣지 않는다. 커밋·push·머지는 사람이 한다.
